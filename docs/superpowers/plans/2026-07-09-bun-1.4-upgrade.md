# Bun 1.4 Upgrade + Benchmark Instrumentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Instrument the landscape benchmark, capture a real Bun 1.3.11 baseline for the effect-TS org, upgrade the site-scoped toolchain to stable Bun 1.4.0, re-measure, and refresh the site figure with the measured number.

**Architecture:** Three independent surfaces — (1) CI workflow instrumentation in `deploy-datasets.yml` with a `benchmark_only` dispatch guard, (2) the `landscape-config.json` org target, (3) site-scoped Bun version pins + regenerated lockfile — followed by two CI-dispatch measurement checkpoints (1.3.11 baseline, then 1.4) and a site copy update.

**Tech Stack:** Bun 1.4.0, GitHub Actions (`oven-sh/setup-bun@v2`), `gh` CLI (authed as `opsydyn`, repo owner), Astro (site).

## Global Constraints

- Target Bun version: **`1.4.0`** exactly (stable). Canary is local-only, never in CI.
- Benchmark org: **`effect-TS`** (promoted to `main` as the published dataset).
- Benchmark duration numbers must be **measured from a GitHub Actions run** — never fabricated, never from a local Mac run.
- The "53 seconds" string is **duplicated** in two independent files; both must be updated together: `apps/site/src/pages/technology.astro:149` and `packages/report-ui/src/views/TechnologyView.astro:145`.
- Version-pin scope is **site only**: do NOT touch `apps/app`, `apps/runtime`, `apps/copilot-runtime` Dockerfiles/engines/@types, or `AGENTS.md`.
- `bun.lock` must be regenerated under Bun 1.4 and committed so CI `--frozen-lockfile` passes.
- Work happens on branch `bench/bun-baseline` (already created).
- Commit message trailer: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

### Task 1: Instrument the benchmark job + add `benchmark_only` guard

**Files:**
- Modify: `.github/workflows/deploy-datasets.yml`

**Interfaces:**
- Consumes: existing steps `landscape` (outputs `dataset_name`) and `storage` (outputs `storage_ready`).
- Produces: step `analyze` with output `landscape_seconds` (integer string); a `workflow_dispatch` boolean input `benchmark_only` (default `false`).

- [ ] **Step 1: Add the `benchmark_only` workflow_dispatch input**

Replace the bare dispatch trigger (line 14):

```yaml
  workflow_dispatch:
```

with:

```yaml
  workflow_dispatch:
    inputs:
      benchmark_only:
        description: "Skip Azure publish; only measure landscape duration"
        type: boolean
        default: false
```

- [ ] **Step 2: Wrap the analyze step with a timer**

Replace the current step (lines 83-88):

```yaml
      - name: Generate hosted landscape dataset
        run: >-
          bun run apps/cli/src/index.ts analyzeLandscape
          --config _landscape-config.hosted.json
          --outputFolder datasets/${{ steps.landscape.outputs.dataset_name }}
          --concurrency 4
```

with:

```yaml
      - name: Generate hosted landscape dataset
        id: analyze
        run: |
          start=$(date +%s)
          bun run apps/cli/src/index.ts analyzeLandscape \
            --config _landscape-config.hosted.json \
            --outputFolder datasets/${{ steps.landscape.outputs.dataset_name }} \
            --concurrency 4
          elapsed=$(( $(date +%s) - start ))
          echo "landscape_seconds=$elapsed" >> "$GITHUB_OUTPUT"
          echo "### Landscape analysis: ${elapsed}s (Bun $(bun --version), org ${{ steps.landscape.outputs.dataset_name }}, concurrency 4)" >> "$GITHUB_STEP_SUMMARY"
```

- [ ] **Step 3: Guard the Azure login step**

Add an `if:` to the "Log in to Azure" step (currently line 121-124):

```yaml

        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}
```

- [ ] **Step 4: Guard the storage-resolve step**
